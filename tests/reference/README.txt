LLaMA GGUF numeric reference

Upstream: https://github.com/ggml-org/llama.cpp
Exact upstream revision: llama-cpp-commit.txt in this directory.
Pairing source: src/llama-model.cpp (LLM_ARCH_LLAMA -> normal adjacent RoPE),
conversion/llama.py (LlamaModel.permute), ggml/src/ggml-cpu/ops.cpp.

The standalone generate_llama_fixture.py creates a tiny complete one-layer
GGUF with GQA, hidden=8, head_dim=4, FFN=16, vocabulary=8 and deterministic
F32 weights. This is a numeric compatibility fixture, not a trained model or
language-quality benchmark. Compare raw prompt token IDs [3,4,5] with F32 KV.

Reproduce:
1. Clone upstream and checkout the recorded revision.
2. cmake -S llama.cpp -B llama.cpp/build -DGGML_NATIVE=OFF -DGGML_OPENMP=OFF
   -DLLAMA_BUILD_TESTS=OFF -DLLAMA_BUILD_EXAMPLES=OFF -DLLAMA_BUILD_TOOLS=OFF
   -DLLAMA_CURL=OFF -DLLAMA_BUILD_COMMON=OFF
3. cmake --build llama.cpp/build --target llama -j 4
4. python3 generate_llama_fixture.py /tmp/nexus-rope-reference
5. Compile llama_logits.cpp against upstream's include/, ggml/include/ and
   build/bin/libllama, libggml, libggml-base, libggml-cpu (C++17).
6. Run the resulting binary with /tmp/nexus-rope-reference/tiny.gguf.

Reference last-token logits:
[-0.382001132,-0.0519405901,-0.0827322602,-0.382497042,
 0.872480154,-0.108524367,0.797122896,-0.0825339258]

Nexus with KvQuantType::None on the same file differed by at most 1.96e-7.
The HF->nexus-convert(F32)->GGUF->Nexus path reproduced the same result.
The permanent engine regression uses the same weight formula with a 3e-6
allowance for scalar/compiler rounding; it distinguishes adjacent-pair RoPE
from the former split-half implementation. Default low-bit KV is intentionally
lossy and is not used for numeric parity checks.

GPU and tokenizer references (2026-11-07)

Additional tools are opt-in and do not download anything during cargo test.
Python reference requirements: tokenizers==0.22.2, Jinja2==3.1.6.
Generate checked-in small tokenizer fixtures with generate_tokenizer_fixtures.py.
Those files contain synthetic vocabularies, not model weights.

Pinned HF tokenizer/model revisions and SHA256s: hf-models.json.
Download tokenizers only:
  python3 tests/reference/download_reference_models.py
Add --with-weights to also download SmolLM2-135M-Instruct (about 269 MB).
Default asset root: ~/.cache/nexus-reference-models
Override it with NEXUS_REFERENCE_MODELS. The Llama-3 and Qwen downloads are
TOKENIZER assets only; these tests do not claim their inference architectures
are supported. Observe the model repository licenses when obtaining assets.

Build tokenizer_reference.cpp against the pinned llama.cpp revision above:
  c++ -std=c++17 tests/reference/tokenizer_reference.cpp \
    -I/tmp/nexus-llama-reference/include \
    -I/tmp/nexus-llama-reference/ggml/include \
    -L/tmp/nexus-llama-reference/build/bin \
    -Wl,-rpath,/tmp/nexus-llama-reference/build/bin \
    -lllama -lggml -lggml-base -lggml-cpu -o /tmp/nexus-tokenizer-reference

Reference defaults use /tmp/nexus-llama-reference/models for upstream vocabulary
GGUFs. Override with NEXUS_LLAMA_VOCABS. NEXUS_LLAMA_TOKENIZER_BIN overrides
the reference executable path.
  python3 tests/reference/generate_external_tokenizer_goldens.py
  cargo test --locked --test external_tokenizer_parity -- --ignored

The two external tests cover SmolLM2, Qwen2.5, Llama-3 HF pipelines/templates
and native llama-spm, llama-bpe, qwen2, bert-bge GGUF vocabularies. The corpus
includes empty/leading/repeated spaces, Turkish, combining accents, CJK, emoji,
control strings, long text and punctuation/quotes that revise BPE decoding.
Goldens are generated by separate Python/C++ processes, not Nexus itself.

Real-model GPU validation:
  cargo run --release -p nexus-convert -- \
    --input ~/.cache/nexus-reference-models/smollm \
    --output ~/.cache/nexus-reference-models/smollm/model-f32.gguf --quant f32
  cargo run --release --features cuda --example compare_cuda -- \
    ~/.cache/nexus-reference-models/smollm/model-f32.gguf
  cargo build --release --features cuda --bins --locked
  python3 tests/reference/cuda_server_smoke.py \
    ~/.cache/nexus-reference-models/smollm/model-f32.gguf

The comparison uses F32 weights and unquantized KV, greedy generation of 32
new tokens, and checks full logit lengths, scaled error and identical token IDs.
The smoke script starts an authenticated localhost server on a temporary port,
checks CUDA counters, chat/SSE equality, decoded-text stops, concurrency,
replacement/reload failure atomicity and device memory release on unload.
It stops its own server at completion. No model is published or uploaded.

CUDA memcheck:
  NEXUS_REQUIRE_CUDA=1 cargo test --features cuda --test cuda_execution --no-run
Run the emitted cuda_execution executable under:
  NEXUS_REQUIRE_CUDA=1 compute-sanitizer --tool memcheck --error-exitcode 99 EXE
Use --test-threads=1 for a serial device memory check. See docs/validation.md
for the current test count and recorded hardware results.
Kernel source is src/backend/kernels/matvec.cu; README.md records exact NVCC
flags. The checked-in PTX was regenerated by CUDA 13.4.3 and compared bytewise.

Recorded validation scope and commands: docs/validation.md.
